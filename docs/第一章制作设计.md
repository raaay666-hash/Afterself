# 第一章：睡过头的人 / 首个 Windows 样机

## 实现前固定的范围

Godot 4、Windows x64、中文、鼠标点选；1280×720 界面与低分辨率场景分离，窗口可缩放。三场景、五名人物、证据收集、三步结案、身份选择、自动存档与新游戏确认。无付费接口，无实时生成，无在线依赖。

## 案件证据链

1. 苏筠证词与桌面日历：最近三天发生了和好与开店计划，宋屿对此没有记忆。只能支持异常，不能证明谋杀。
2. 宋屿证词与恢复登记：备份取自三天前，今晨 06:12 启动现行实例。证明替换，不独立证明执行者。
3. 走廊维修单：邵为负责夜间维护。只证明机会与权限。
4. 门禁签收：02:14 邵为领取一次性维修凭据，02:41 才归还；邻居确认其间本人进出，柜台无再次签发。限定凭据控制范围，仍不单凭工牌指认。
5. 档案室只追加执行回执：02:26 同一一次性凭据签署终止指令，目标为旧宋屿；06:12 同一工单执行恢复。回执由独立审计端保存，住户管理处无法回写。
6. 旧便条：旧宋屿发现违规清理名单并约定次日举报；维修单有要求删除对应附档的备注。结合邵为对质承认，补足掩盖记录的动机。

这些为虚构世界的案件规则，不主张电子签名在现实中天然不可伪造。游戏内允许询问凭据是否外借、回执是否可覆盖；闻遥解释审计来源。实际司法判断比这更复杂。

## 互动和状态

每个线索可重复查看；收到证据不删除原文本。每个场景显示可操作热点，避免找像素。未收齐关键证据也能打开案卷，系统提示缺少哪类支撑，不能直接结案。关键证据不能被错选永久消耗。

结案三问：发生了什么（旧实例终止、旧备份恢复）；谁执行（邵为及其独占凭据和回执）；为何执行（阻止违规清理被举报）。每一问必须同时选择对应证据。答错保留调查进度并给可理解的反证。

结尾身份报告：单列现行实例 / 沿用原档案并注明中断。两种写法都明确旧实例死亡；不提供“恢复等于复活”的事实性选项。宋屿表达希望单列记录的意愿，忽视该意愿会得到不同反馈。保存选择供后续章节使用，本样机不声称已实现六章分支。

## 验收

能从新游戏进入三个场景；全部证据可获取；缺证或错配无法结案；完整证据与正确推理能结束；两种身份报告产生不同反馈；退出重开保留进度；坏存档不会崩溃。以自动流程与截图检查基础实现，真实玩家时长、手感和美术验收仍待试玩。
