## 复现与修复

对第一次交付的已编译安装器进行独立故障注入，在隔离目录复现了以下问题。没有使用用户真实文件。

1. 路径检查把 `C:relative-install`、`\relative-root-install` 及末尾带点／空格的目录视为有效。修订版在归一化之前校验输入，只接受包含盘符的完整本机路径，并拒绝 Windows 保留名称、额外冒号及末尾点／空格。
2. 目标目录检查通过后，如果另一个写入者创建了 `Uninstall.exe`，安装器会失败，但旧回滚会误删这个未由本次安装创建的文件。修订版只在成功创建文件后将其加入回滚清单。
3. 在登记安装信息之前出现同名安装回执，旧版会覆盖它。回执现在使用 `CreateNew`，有冲突就失败回滚并保留该文件。
4. 回滚遇到被占用的文件时，旧清理会中断。修订版逐项清理并收集失败项，继续处理其余文件，并准确报告不能清理的文件。

同时增加安装／卸载的互斥入口，避免两个生产程序同时操作文件与登记；安装完成后若游戏启动失败，会保留完成页并显示原因，不因启动异常崩溃。

复现结果：`build/installer-distribution/before-fix/core-results.json`。修复后结果：`build/installer-distribution/qa-core/core-results.json`。独立检查源码为 `installer/CoreRegression.cs`，通过反射调用最终已编译安装器，覆盖真实创建、真实锁定及真实回滚，不以测试替身代替这些操作。

安装器的九项隔离安装与卸载检查通过；新增八项边界检查通过，包括四种非法路径、两处同名文件冲突、文件占用时的继续清理、并发程序入口拒绝。

## 边界

本轮未发现阻断通关的问题，检查通过不能证明没有任何潜在问题。没有跨电脑 Windows 兼容性、真人难度／时长或主观听感验收，程序未签名。

隔离安装检查不写用户桌面、正式 HKCU 卸载登记或 AppData 玩家存档，因此 Windows“已安装的应用”界面入口仍没有通过该实际入口操作验收。默认完成后启动游戏的按钮增加异常处理；游戏本身由独立 EXE 检查，不宣称默认日常路径已操作验收。

旧首次安装器保留在 `build/first-installer/` 作为构建记录。分发使用本次修订 2 ZIP，避免继续使用已发现边界问题的旧安装器。
