# 启动阶段 · 六章一周目可玩版

当前版本：0.10.0 / 2026-10-01。Windows x64，Godot 4.5.1，离线运行。

2026-10-02 已完成第一版整合发行包，并在二次复查后修订安装器。当前分发使用 `build/installer-distribution/Afterself-0.10.0-Windows-x64-Installer.zip`，解压后运行 `Afterself-Setup.exe`，安装器内含完整游戏。修订 2 修复相对路径、同名文件冲突／回执覆盖与异常回滚问题，并增加安装卸载互斥。旧首次安装器保留作构建记录，由本次修订替代。免安装包仍可使用 `build/first-installer/Afterself-FirstBuild-0.10.0-Windows-x64.zip`。游戏内部版本仍为 0.10.0。

安装到空目录；卸载保留 `%APPDATA%/StartupPhase/` 存档、修改过的文件和用户自行添加的文件。最新成品与 SHA-256 见 `build/installer-distribution/package-verification.json`。首次制作与验收记录见 `docs/第一版整合打包-2026-10-02.md`。重建运行 `scripts/build_first_release.py`，须使用本机已有 Godot 4.5.1、Windows .NET Framework 编译器和提供 Pillow 的 Python；玩家不需要这些开发工具。

最新安装包的哈希和 ZIP 检查见 `build/installer-distribution/installer-zip-verification.json`，二次复查记录见 `docs/复查与独立安装包-2026-10-02.md`。`scripts/package_installer_distribution.py` 在游戏和安装验收通过后生成包含安装器、安装说明、检查结果、校验值和清单的独立安装包 ZIP。

## 开始游戏

运行 `build/v10/windows/StartupPhase.exe`。分发使用 `build/StartupPhase-0.10.0-Windows-x64.zip`，解压后运行，无需安装引擎或开发工具。旧版构建与压缩包保留。

0.10 新增十二段主线现场操作与六件可选小谜题。粗像素近景包括黄铜日期锁、门锁保险芯、地图灯箱、地契套版、索引柜、旧式纸带、抄本页脚、双城仪表、故障日志、只读接线模块、遮罩验证卡与核票台。第一、二章现场门保持开合状态；操作直接解锁相关记录，原有重复排序、下拉推演与旋转管线合并到新流程。

第一章底部“现场操作”、后五章“现场推演”、案卷“现场核验”与标题“现场操作”都进入同一目录，可回访已开放章节。数字锁可用键盘输入，其他操作可用鼠标两次点选，无需精确拖动。每步有三级提示、错误反馈、原件回查与部分进度保存。维修门还可向闻遥申请同源签收副本，仍要核对邻居和本人证词；界面注明通过副本取件，没有伪造修门记录。

十二段主线共23步，六段可选各1步。谜题答案与新增线索由 `scripts/build_fieldwork_data.py` 编写，生成 `assets/fieldwork-v10.json`；可编辑像素美术在 `scripts/puzzle_art.gd`，阶段状态与界面在 `scripts/field_puzzles.gd`。设计与具体流程见 `docs/现场解谜美术与制作流程-v0.10.md`，验证见 `docs/现场解谜验证-v0.10.md`。

0.9 新增证物柜：37 份主线记录、12 件可选人物物件，全部沿用 32×32 少色模型。未收集格子保持空白，不显示名称、图像或提示。首次获得时弹出“新证物已收集”，可立即检查或稍后查看；关键对白与选择结束后才显示通知。检查页支持正面、背页和可点击细节，已检查位置随存档保留。已获得的证物可反复查阅，不消耗、不重复弹出收集通知。

标题可直接打开证物柜；调查中从 J 案卷“逐份重读证据”或后五章“记录原文”进入。人物询问菜单和柜内提供“物件委托”，满足证据、对白或剧情条件后可自愿接受；先完成当事人对白，再收录获准的记录。原物保管与公开范围按故事约定，人物物件不作为新增独立证明。规则与验证见 `docs/证物收集交互-v0.9.md`。

暂停菜单中的人物档案现在从调查进度解锁：未遇见的人物只有暗色占位卡；人物出场或开口后点亮卡片；证据、结案与跨章揭示会逐条补充已知记录。第一章不会提前显示现实林砚等后期身份，询问菜单也只写当下已知的身份。已有存档会从可验证的章节进度补回人物记录；新的相遇会随全篇进度保存。详见 `docs/人物档案渐进解锁-v0.8.md`。

新游戏先播放四幕像素开场：城区与主角、苏筠报案、邻居与管理处的矛盾说法、到场后的调查目标。镜头缓慢平移并淡入；前三幕约每幕 9 秒自动推进，也可点击、按空格或回车提前继续。最后一幕等待玩家选择“进入调查”。Esc 或“跳过开场”直接进入第一章到场对白。中途退出会从开场重播，不会跳过未听到的交代。剧情设计与剧透边界见 `docs/开场演出设计-v0.7.md`。

可从第一章顺序游玩，在结案卡进入第二章；已有 v6 / v5 进度会作为首次接续来源，首章也支持回读 v4。标题提供“从第二章开始”，进入前明确说明采用的首章记录，不悄悄替玩家编造已做的选择。

鼠标点选调查，主角走近后阅读或交谈。底部切换场景。H 显示热点，J 打开案卷，空格推进对白，Esc 暂停或关闭普通面板，M 静音，F11 全屏。关键选择需明确选项，不能用 Esc 跳过。各现场人物可提供该处记录副本，另有调查与推演提示。

## 0.6 调查体验

内置 Fusion Pixel 中文字体，使用 20px 小字和 24px 正文，关闭抗锯齿并增加对白行距。后五章也能显示独立归档回执；证据原件使用穿孔纸张与留存标记。字体的全部授权声明随发布包提供。

J 案卷新增“现场核验”和“故事脉络”。0.6 的夜班时点复原、地图差异、授权排序、双城计量接线、只读通信接线和附件比对，已在0.10合并或改造成现场流程；旧核验状态仍兼容保存。首次对质前需要完成本章两段主线操作，已进入对质的旧存档不被重新阻断。

故事脉络包含全篇线索索引、逐章摘要、24 张故事卡、来源记录与本次选择。只开放已完成的章节和章末事件；直接进入第二章不会伪造首章通关。故事卡默认按顺序显示，也可交换卡片自行复原并保存“已梳理”标记。证据结论可以点开查看解释及两份支持原件。

0.6 调查与复盘记录继续兼容。原版测试与验证见 `docs/调查体验验证-v0.6.md`，设计见 `docs/调查体验重设计-v6.md`。

## 六章内容

| 章节 | 案件 | 现场操作 |
|---|---|---|
| 1 睡过头的人 | 终止被恢复掩盖 | 日期锁、保险芯开门、四时点与凭据保管区间 |
| 2 没有玩家的游戏 | 假地契与真实居民 | 地图平移旋转、账房路线、套版查询、地块分类 |
| 3 同一个凶手 | 三种不同来源的同名签名 | 原卷索引、竖列纸带复原、三条签名来源 |
| 4 神谕版权案 | 被删改的水源条款 | 抄本页脚拼接、仪表校正、三个情境条件验证 |
| 5 越界来信 | 冻结事故与另一次删除 | 日志分批、只读排障、四模块接线、遮罩短语 |
| 6 全体同意 | 历史副本重复投票 | 六张样例票及理由、两端附件灯箱、事实更正包 |

后五章共 30 份记录、15 项证据推论、15 轮对质、15 次场景访问及四段需要查阅文件后作答的幕间。九张环境底图含五张新制作场景，并按章节复用档案室等地点。保留第一章生活支线与告知事件。

三种公共方案各有收益与代价；之后再单独选择上传或不上传，共六种结尾组合。第一章身份与生活安排、第二章证人身份、第三章实例归档、第四章共同核验方式、第五章名册去向，会改变尾声中的具体回应。没有以恢复撤销死亡，也没有把上传描述为已证明的意识转移。

## 美术与声音

首章已认可的五人素材保留。后七人采用与既有网格相接的 20×40 连贯少色上身，再绑定到同一 25 骨骼系统；全部角色通过 80×80 透明画布呈现粗像素轮廓。共享步行动作、脚步相位和 IK，不宣称十二套独立动画。

五张新环境使用内置 imagegen 生成，原文件复制到 `assets/scenes/oldquarter-v5.png`、`clinic-v5.png`、`waterworks-v5.png`、`server-v5.png`、`boardroom-v5.png`。提示词完整保存在 `docs/场景提示词-v5.md`。场景在 320×180 网格采样后放大，UI 文字保持清晰。人物后七人由可编辑程序逐像素构造，没有替换首章上身图像。

保留七类程序合成音频，室内雨声衰减。没有配音或口型同步。

## 存档

存档目录 `%APPDATA%/StartupPhase/`：本版第一章 `chapter1-v10.json`，全篇进度、现场操作、人物物件、检查位置与偏好 `campaign-v10.json`。首次可读取已有 v9、v6、v5；首章还会尝试 v4。旧文件不写入、不覆盖。已取得主线证物保留，已开始对质或已结案不因新增操作阻断；回访不伪造当时已玩过的新谜题。关键回应未播完会从段落开头重播；章节只有结案与幕间均完成才解锁下一章。

全篇保存采用临时文件替换；读取时校验证据依赖、推演、对质、选择及章节解锁。测试使用发布目录内独立文件，不读写玩家进度。

## 制作边界

这是六章主线已贯通的可玩版本，仍需玩家反馈打磨节奏和可发现性。原定三小时没有经过陌生玩家实测，不作为当前版本的已验证时长。二周目尚未制作，界面不提供虚假的可玩入口。一周目的必要真相及公共、私人结局在本篇交代。

没有跨设备 Windows 兼容性验收或主观音频听感验收。程序未签名。章节美术是像素背景、骨骼角色与界面演出，没有制作逐帧过场电影。

## 开发与验证

入口 `scripts/campaign.gd` 承接 `scripts/game.gd` 的首章；后续流程在 `scripts/campaign_flow.gd`。`scripts/build_campaign_data.py` 保存可编辑的剧情源，生成导出的 `assets/campaign-v5.json`。人物上身像素逻辑在 `scripts/cast_pixels.gd`。

Godot 运行参数放在 `--` 后：`--self-test` 为首章及动作回归；`--campaign-test` 为后五章分支、依赖与存档；`--full-story-test` 或 `--field-story-test` 为实际窗口从第一章新谜题贯通最终私人结局；`--campaign-window-test` 为后五章独立接续入口；`--field-test` 检查十二段主线、六段可选、依赖、错误解与保存回读；`--field-window-test` 用真实鼠标、键盘操作全部二十九步并截图；`--desk-test` 检查旧核验状态、复盘、字体覆盖、存档和剧透边界；`--desk-window-test` 保留旧核验回归；`--collection-test` 检查证物、通知、热点、12 件委托与存档；`--collection-window-test` 检查空柜、收集、翻面和委托；`--audio-smoke` 为音频加载与退出。测试日志应指定工作目录内的绝对 `--log-file` 路径，测试不读写玩家存档。

原六章设计见 `docs/第二至六章制作-v5.md`，世界观源见 `docs/原始六章剧本.md`，人物档案规则见 `docs/人物档案渐进解锁-v0.8.md`，验证见 `docs/人物档案验证-v0.8.md`。证物交互在 `scripts/evidence_collection.gd`，可编辑热点说明在 `scripts/evidence_hotspots.py`，运行数据由 `scripts/build_evidence_runtime.py` 生成。导出目标 `build/v10/windows/StartupPhase.exe`，打包脚本 `scripts/package_windows.py` 只收录成品、说明及许可证。
